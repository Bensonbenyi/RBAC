| demo-client | 6 | 85/85，100% | 30/30，100% | 通过 |

89 项测试失败、错误、跳过均为 0。原始报告源版本为 `a12e0170012a3a31f313cf6939bbb1a3d9dd5a3c`，后端测试范围的未提交差异摘要是空内容 SHA-256。后续提交补浏览器测试、Nginx、文档和源码中文注释，未改变其后的业务执行逻辑。原始[verification.json](verification/coverage/verification.json)包含逐套件结果、工具版本及运行时间；[控制台](verification/coverage/console.txt)、[完整报告包](verification/coverage/jacoco-reports.tar.gz)与[校验和](verification/coverage/SHA256SUMS)同时归档。

## 浏览器与服务器验证

同一组六项 Playwright 场景分别在本机与公网通过：本机 12.5 秒，公网 32.8 秒；无跳过、无重试后通过。报告为[本机](verification/oral/local-browser-tests.json)和[公网](verification/server/browser-tests.json)。公网功能等待窗口为 15 秒，以容纳首次资源下载；这是功能测试等待期限，不是性能达标证据。

| 场景 | 验证结果 |
| --- | --- |
| 管理界面 | 中文导航、角色权限选择、影响确认、员工授权撤销、有效权限和日志导出通过 |
| OIDC 与两个系统 | 跳转登录、跨系统免再次输入身份、OA 与知识库权限差异、本人范围拒绝通过 |
| 无授权及范围 | 普通员工可确认身份，但无业务角色时拒绝操作，不能进入管理后台 |
| 撤权 | 在已允许的浏览器会话中撤权，随后受控操作拒绝，观察时间小于三秒 |
| 员工停用 | 停用后已有会话受控操作拒绝；重新启用不能恢复该会话或旧角色 |
| 统一退出 | 一个系统退出后，另一系统的后续受控操作拒绝 |
| 重启 | 平台重启后旧客户端令牌拒绝；重新发起 OIDC、登录后恢复原有效权限 |
| 持久化 | 重启前后公司、部门、员工、系统数量和受测分配、员工状态一致 |

重启的[前](verification/server/persistence-before.txt)、[后](verification/server/persistence-after.txt)查询结果逐字比较一致。旧客户端页面在重启后仍可能显示原身份，受控操作实际拒绝；重新访问客户端的 `/oauth2/authorization/upms` 或用新浏览器会话重新登录。模拟业务记录为内存演示数据，客户端重启后不保留。

首轮并行运行曾共用 Playwright 产物目录，造成 ENOENT；公网首次加载也遇到默认五秒等待不足。已按目标分开 trace、HTML 和 JSON 目录，增加公网功能等待窗口、开启静态 gzip 后重跑通过。[初次失败控制台](verification/server/browser-initial-console.txt)保留，不将失败轮次写成通过。

Manager 运行平台与 Nginx；Node1 运行专用 MySQL 和两个客户端。两台均约 2 CPU / 1800 MiB，平台 Xmx512m，两个客户端各 Xmx128m，MySQL buffer96m。资源与构建 SHA-256 见 [Manager](verification/server/manager-runtime.txt)、[Node1](verification/server/node-runtime.txt)，部署及恢复方法见 [infra/server](../infra/server/README.md)。这是运行快照，不是容量实验。

443、8443、9443 使用可信 IP HTTPS 证书，浏览器和测试未忽略证书错误。短期证书每六小时检查续期，[renew --dry-run](verification/server/certificate-renewal-dry-run.txt)已成功。原课程 Swarm 业务及 MySQL 缩为零副本，数据和配置保留，监控继续运行；按恢复脚本顺序可恢复。

本轮没有在这两台小内存服务器重跑万人正式压测。原五项性能验收在[历史报告](最终验收报告.md#正式结果)记录了本机硬件、请求构成、成功与失败轮次；新增保持行为的调整通过回归，但不能据此宣称新服务器容量达标。
