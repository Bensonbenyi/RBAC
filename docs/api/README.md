## 登录、查询与退出

1. 选择目标环境，发送“服务就绪”，再获取登录前 CSRF。
2. 把响应 `token` 填入登录 Body 的 `_csrf`，替换 `{{csrf}}`。虚拟演示账号见[项目 README](../../README.md)。
3. 发送登录请求。客户端可能跟随 302 返回 HTML，须通过“当前管理员”的 200 JSON 确认身份。
4. 重新获取登录后的 CSRF。查询使用会话 Cookie；写入和退出将最新 token 填入 `X-CSRF-TOKEN`。
5. 退出后“当前管理员”应返回 401。集合中成功断言预期 200，退出后断言失败属于此项验证的预期结果。

Apifox 的 Cookie Jar 与浏览器分开；浏览器登录不会让 Apifox 自动获得身份。本机统一使用 `localhost`；服务器统一使用 HTTPS IP 地址。CSRF、Cookie、Bearer、手机号及客户端密钥保存在个人临时调试值中，不保存到共享示例。

本机 Apifox 已实测登录、管理员身份、公司和员工查询及退出后的 401。公开服务器的浏览器和接口回归结果见[口试交付验收报告](../口试交付验收报告.md)，不把结构示例当作全量接口实测。

## 离线集合

[upms.postman_collection.json](upms.postman_collection.json) 可在 Apifox 的 Postman 导入入口导入。离线集合的 `baseUrl` 默认 `http://localhost:18080`；需要访问服务器时改为 `https://113.44.144.119`。Apifox 导入可能将环境命名为 Production，判断连接位置应看实际 URL。

`Params` 是筛选分页，`Body` 是写入示例，`Headers` 是 CSRF 或 Bearer。编号 `0`、空密钥和 `{{csrf}}` 均为待填写占位；版本来自最新查询。集合含撤权、停用和凭据轮换，按需逐条执行，不整包运行。整批接口不能代替从两个模拟系统发起的完整 OIDC 登录。

文档由源码手工核对，未接入自动 OpenAPI 生成；代码变化后须同步复核。操作契约和关系设计见[接口与数据库设计指南](../thinking/统一权限管理系统接口与数据库设计指南.md)。
