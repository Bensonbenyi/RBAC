## 继承和直接授权

部门以 `parent_id` 形成树，每个部门只有一个直接上级。角色继承允许多路径，存储时直接把每条继承关系记为一条边。设箭头从高级角色指向基础角色。同一个基础角色 D 可以同时通过 A → B → D 和 A → C → D 给 A 提供权限。删除 B → D 后仍有第二条路径，删除 C → D 后才失去 D 提供的权限。新增 A → B 前，从 B 沿现有边查找 A 即可判环。两套实现共用 `RoleHierarchy.requireAcyclic`，检查只使用本次读到的边、待访问队列和去重集合。新增边仍锁本部门一行，因为两个反向新增可能各自通过检查，合在一起却形成环。删除边只能减少可达路径，由普通事务删除指定关系即可。 [RoleHierarchy](../../backend/src/main/java/cn/edu/xmu/rbac/service/role/RoleHierarchy.java)

联合主键直接处理重复授权。用户分配角色时，Service 核对操作许可、用户和角色的部门，再写 `user_role`。DDD 由 `User` 校验目标角色归属，两个实现均由 MySQL 拒绝重复分配，统一返回 409。授予角色权限时先读取目标角色与权限，通过关联表的幂等写入返回 204。删除了写前的查重和整组关联读取。JUnit 契约继续检查同部门、重复分配、幂等授予、权限缺失及旧令牌实时撤权。

## 文件职责与教师示例

`JdbcManagementStore` 从 397 行减到 345 行，负责目录、直接授权和继承边的读写。`JdbcEffectiveAccessStore` 负责将直接角色沿继承关系展开。在 SQL 中，起点可以是指定角色，也可以是用户的直接角色。递归部分使用 `UNION DISTINCT` 合并多路径到达的同一角色，最后由各查询选择角色名、系统内权限码或权限记录。单独读端口让认证、鉴权和角色页面能共享闭包语义。在 Vue 角色页面，授予和撤销共用提交入口，成功后只刷新直接授权列表和当前身份，候选系统在打开配置面板时读取。 [有效授权查询](../../backend/src/main/java/cn/edu/xmu/rbac/infrastructure/persistence/JdbcEffectiveAccessStore.java)
