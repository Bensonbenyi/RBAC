# v3.6.2 Spring Data JPA 整改

按课程评分要求，应用数据库访问统一由 Spring Data JPA 仓储完成。目录、用户角色、角色权限、角色继承及登录会话均映射现有表。普通读取、分页和新建使用生成的仓储方法，关联投影和批量更新使用仓储声明的 JPQL。结构化和 DDD 共用这组仓储，持久化实体在适配器内转换为业务 Data。MySQL 驱动提供连接，Flyway 保留历史迁移，Hibernate 启动时校验实体映射。

角色继承按层批量读取基础角色，角色编号集合负责合并多条路径。赋予相同权限的并发请求锁同一个角色行，在提交前合并同一个联合主键，保持两次 PUT 均成功。新增继承边仍在部门锁内执行防环。直接关系的撤销由 JPQL 删除处理，关联已不存在时也可完成。两种实现通过相同契约验证这些行为。

概要设计、详细设计和 StarUML 的架构、模块类图与持久化时序均已对应到 JPA。 [设计交付](../redesign/README.md) [测试汇总](test-summary-v3.6.2.json)

平台 43 项测试、CloneFactory 5 项、前端 4 项全部通过。结构化与 DDD 分别对真实课程后端通过 58 项本地联调。把 v3.6.1 平台容器替换为 v3.6.2 后，JPA 在同一数据库上通过映射校验，升级前签发的会话可以继续读取本人身份。 [结构化联调](acceptance-v3.6.2-local-structured.json) [DDD 联调](acceptance-v3.6.2-local-ddd.json)

本机 amd64 容器沿用 384 MiB 内存上限。DDD 混合授权查询在 8 并发下完成 1,000 次请求，均返回 200，P95 为 282.74 ms，未发生 OOM。容器触及内存上限，Swarm 的资源余量需按部署后的负载观察。 [本地压测](benchmark-v3.6.2-local.json)
