# v3.6.0 身份接口与代码精简整改报告

2026-11-20 完成老师统一身份鉴权接口对齐、课程系统适配、DTO/VO 分层和本地联调。业务范围保持 RBAC、单部门、两个接入系统和结构化 / DDD 双实现。

## 接口对齐

| Apifox 接口 | 实现路径 | 结果 |
| --- | --- | --- |
| 登录 | `POST /auth/login` | 接受 username、password、systems，systems 允许多个不重复目标系统，JWT aud 保存目标系统列表 |
| 退出 | `POST /auth/logout` | 撤销当前持久化会话 |
| 当前身份 | `GET /auth/me` | 返回 subject、no、name、departmentId、roles、permissions |
| 界面权限 | `GET /auth/permissions/{permission}` | 仅返回 allowed |
| API 权限 | `GET /auth/api-permissions/{operationId}` | 已知操作返回 allowed，未知操作返回 `API_OPERATION_NOT_FOUND` |
| 部门目录 | `GET /auth/departments` | 支持 parentId、keyword、page、pageSize 和 hasChildren |
| 部门用户 | `GET /auth/departments/{departmentId}/users` | 分页返回身份字段，不返回手机号或邮箱 |
| 用户查询 | `GET /auth/users/{userId}` | 返回 userId、no、name，使用老师的路径和错误码 |

老师课程后端继续通过 Spring HTTP Interface 调用身份服务。`UnifiedIdentityClient` 负责当前身份和用户查询，`ApiAuthorityClient` 负责课程操作权限。课程过滤器把 Bearer、目标系统和 operationId 传给身份平台，每次请求实时检查权限。

## 代码结构

平台输入模型位于 `api/*/dto`，输出模型位于 `api/*/vo`。Controller 使用 `@Valid` 完成字段校验，并负责 DTO、VO 转换。CloneFactory 处理同名字段拷贝和 PATCH 非空字段合并。Service 保留权限、部门范围和业务规则，ManagementStore 保留 SQL 查询和持久化。

目录查询复用现有 department、app_user 数据和索引，通过投影查询生成 `DirectoryDepartment`、`DirectoryUser`，没有新增业务表。解除角色继承直接删除关联边。新增继承仍锁定部门行并在 READ COMMITTED 下读取当前边，因为并发新增反向边会共同破坏无环约束。

代码中移除了业务 Service 的散落日志和多余的解除继承锁，统一由 LayerLogging 记录 Controller、Service、Infrastructure 的操作、结果和耗时。保留认证过滤器对请求状态的必要记录。
