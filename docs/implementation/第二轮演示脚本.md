## 助教检查

在 Swarm Manager 执行 `docker stack services rbac_v33`。四项服务分别是入口、权限后端、课程后端和 MySQL。入口提供两个前端，课程系统的身份和 API 许可来自权限平台。

用管理员进入权限后台，依次打开用户、角色、部门、业务系统、权限目录和个人资料。另开终端执行 `docker service logs --since 1m -f rbac_v33_rbac`，按同一请求的线程名找到 Controller、Service、JPA 仓储的 Logback 记录。部门树中展开「规模演示组织」，可以查看来源部门的上下级。用户页按操作者所属部门查询。

| 菜单 | 请求 |
| --- | --- |
| 用户 | `GET /api/users` |
| 角色 | `GET /api/roles` |
| 部门 | `GET /api/departments` |
| 业务系统 | `GET /api/systems` |
| 权限目录 | `GET /api/systems/{systemId}/permissions` |
| 个人资料 | `GET /auth/me` |

## 教师检查

| 需求 | 页面演示 | 测试或图稿 |
| --- | --- | --- |
| 用户角色分配 | 为本部门用户分配并撤销角色 | `ManagementContract.assignsAndRevokesRoleWithConflictAndIdempotence`；USER-07 的两套时序及 DDD 聚合续图 |
| 同部门与多级继承 | 高级 → 中间 → 基础，另加高级 → 基础。删除直达边后权限仍有效，再删间接路径后权限消失；尝试基础 → 高级会被拒绝 | `RbacContract.inheritsAcrossMultiplePathsAndRevokesForExistingTokens`；ROLE-11 的两套类图和时序 |
| 目录只读 | 查看部门、业务系统和权限目录，在角色页面授予已有权限 | `ManagementContract.readsCatalogsWithoutWriteEndpoints` |
| 课程接入 | 普通教师能看课程，缺少审核 UI 码时按钮禁用；持有审核 API 码时由平台返回许可 | `IdentityContract`；`tooling/acceptance.py`；COURSE-07 |
| 对象拷贝 | 新建或重命名角色时，Controller 使用 CloneFactory 将名称 DTO 拷贝为用例输入 | `CopyTest`；对象拷贝时序图 |

USER-07 中结构化服务直接检查目标角色所属部门，DDD 应用服务调用 `User.requireRoleInDepartment`。ROLE-11 中两套实现共用继承遍历。结构化服务调用防环规则，DDD 的 `Role.requireBaseRole` 结合自身部门和可达集合维护不变量。以领域对象负责其归属和继承规则说明 GRASP 的 Information Expert，以两个实现共用同一用例端口说明 Polymorphism。

| 课程请求 | operationId | 许可码 |
| --- | --- | --- |
| `POST /terms` | `createTerm` | `TC` |
| `PATCH /terms/{id}` | `updateTerm` | `TE` |
| `DELETE /terms/{id}` | `deleteTerm` | `TD` |
| `GET /admin/courses`、`GET /courses/{id}` | `listAdminCourses`、`getCourse` | `CV` |
| `POST /courses/{id}/review` | `reviewCourse` | `CR` |

`BACKEND_STRATEGY=structured` 或 `ddd` 在启动时选用实现。两套实现运行同一组 MySQL 契约测试。用 `./tooling/test.sh` 复跑，报告在 `backend/target/site/jacoco/`。JavaEE 抽查沿 HTTP 请求讲 Spring MVC、校验、Spring Security、用例装配、JPA、事务、Flyway、CloneFactory 和 Logback。
