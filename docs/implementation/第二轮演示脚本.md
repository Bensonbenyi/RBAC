### RBAC1 多级继承与撤权

1. 给“基础”角色授予一项演示权限。配置“高级”继承“中间”，“中间”继承“基础”，并再加“高级”直接继承“基础”。
2. 查看“高级”的有效权限，同一权限只出现一次。把高级角色分配给同部门临时用户，使用其当前会话访问对应业务。
3. 尝试基础继承高级、自身继承自身，均返回 ROLE_CYCLE / 409。
4. 删除高级到基础的直达边，中间路径仍使权限有效；再删除中间到基础的边，原会话立即失去该继承权限。
5. 删除剩余测试关联、临时用户及角色。对应 inheritsAcrossMultiplePathsAndRevokesForExistingTokens、rejectsHierarchyCyclesScopeAndReferences；并发保护见 serializesConcurrentOppositeInheritanceWrites。

### GRASP 与配置切换

选 ROLE-11 说明 Information Expert：RoleHierarchy 持有边快照并判断无环；Creator：应用服务装配该对象；Low Coupling 和 Protected Variations：业务依赖端口，持久化独立实现；Polymorphism：两个业务实现遵守同一 RoleUseCase。

通过 BACKEND_STRATEGY 选择平台实现，通过 APP_BACKEND_STRATEGY 选择老师课程后端实现，重启后生效。可使用现有 [结构化](acceptance-v3.6.0-structured.json) 和 [DDD](acceptance-v3.6.0-ddd.json) 两份真实联调记录展示相同 58 项检查结果。现场切换前安排重启时间，恢复后确认两个服务健康。
