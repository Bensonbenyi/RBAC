## 漏项与整改

| 检查项 | 原问题 | 本轮结果 |
| --- | --- | --- |
| 独立界面权限 | 菜单和按钮复用了 API 码 | 平台 22 个 ui.* 码、课程 6 个界面码分别经角色授予；复用 permission 和 role_permission |
| 菜单禁用 | 无权限菜单被隐藏或无法完整展示菜单组 | 有任意管理菜单码时显示管理组，缺码菜单使用原生 disabled；路由同步校验 |
| 按钮和表单 | 审核、保存、授予及撤销未完整遵守按钮码 | 业务条件满足时显示按钮，按独立码禁用；保存及提交同步检查，API 保留服务端许可和对象规则 |
| 身份与权限接口 | 当前身份混入 API 码，界面检查与 API 判断边界不清 | /auth/me 与 /auth/permissions 仅输出或判断已登记界面码；AuthService 映射 operationId 到 API 码，未知操作返回 false |
| 课程适配器 | 将身份响应中的 permissions 当成后端权限 | 通过实时 API 决策，将本次获准的 API 码传给老师业务安全规则 |
| 授权候选目录 | 分配角色或权限依赖无关的完整目录管理权，选项截取单页 | 补三个只读候选接口；本部门角色按授权任务读取，系统与权限按用途读取，前端遍历有界分页 |
| 既有库迁移 | 仅空库演示数据包含新增权限 | Flyway V2 补界面目录并一次性继承原版页面授权；之后 UI 与 API 可以独立撤销 |
| 老师新版安全装配 | 上游新增安全配置与接入过滤器重叠 | 集成 profile 选择单一安全链，固定最新提交及适配补丁 |
| 课程当前身份及详情 | 缺少 GET /me 接入和实际详情读取 | 登录后调用 /course-api/me；详情调用 getCourse；补教师映射初始化 SQL，实际编号跨库关联，重复执行保留现有资料 |
| 撤权刷新 | 页面在权限变化后继续保留旧界面状态 | 窗口重新聚焦、手动刷新及 403 后更新权限，收起已失去许可的页面内容 |
| 对象拷贝 | 部分更新未使用新版非空拷贝能力，编译依赖进入运行包 | 用 copyNotNull 保留未提交字段，新增拷贝测试；运行包保留生成的 CloneFactory，排除处理器及编译依赖 |
| 代码规范 | Java、Vue 和 TypeScript 格式混杂 | Java 使用 Google Java Format、Google Checkstyle，前端使用 Prettier；补充边界规则、数据契约和关键方法的中文 Javadoc |
| 图稿语义 | 成员依赖混画、包图重复、执行说明和回复编号不规范 | 持有字段用关联并标字段名，临时使用用依赖；四种包图分别表达完整关系、分层总览、入口与实现；逐次调用建执行说明，回复不编号，创建对象头部延后，静态 CloneFactory 标 MetaClass |

菜单码与 API 码的组合分别验证：只有 API 码时界面不开放；只有界面码时服务端仍拒绝无许可操作。手机号作为密码输入的约定、Bearer JWT 与持久化会话、单部门管理范围及双实现配置保持当前基线。

CloneFactory 最新上游版本仍为 **0.0.2**，本地 vendor 已包含最新 record、final 和 copyNotNull 支持；本轮核对 22 个文件的 SHA-256，并更新调用和打包配置。证据见 [上游校验](clonefactory-v3.4.0.json)。

## 图稿与文档

交付共 140 张黑白图稿：137 张 UML 及架构图，另有陈氏 ER、业务表关系和技术会话表三张图。图元采用人工坐标排版，并提供 StarUML 原生模型。九张 DDD 聚合修改续图与服务交互通过 UML InteractionUse 对应；详细交互仍放在各功能下面。

两份文档保留 v3.2.2 的字体、字号、页边距、蓝灰用例表及三列调用说明，统一 A4 纵向。需求与详细设计 166 页，概要设计 29 页，分别引用 134 和 14 处图。已检查全页渲染及关键图的高清页面，修正孤行分页。模型 ID 与引用解析通过，140 张 SVG 文字均在画布内。详见 [文档检查](document-check-v3.4.0.json) 和 [图种对应](../redesign/课件图稿对应清单.md)。

已在单个 StarUML 窗口载入原生模型，打开模块类图并核对图元。黑白模型采用浅色主题查看，保留原始颜色；实现关系在该主题下显示为虚线空心三角。交付包保留 redesign 与 implementation 的同级目录，文档和验证记录的相对链接保持一致。
