# v3.8.0 第二轮验收整改

按老师 2026-11-08 发布的 V4 核对第二轮要求。平台和课程系统的前后端部署在同一个 Swarm。用户与角色各归属一个部门，角色可获得两个系统的权限。两套实现通过 `BACKEND_STRATEGY` 选择，共用 API、数据库和前端。 [评分办法 V4](../OOAD_Grading_2026_V4.pdf)

1. **角色。** 后台提供新建、改名、删除、分配、授权、撤权及继承。有效权限按继承图取可达角色的权限并集。同部门校验、防环、外键和组合主键负责业务一致性。写入使用常规 JPA 事务，提交期间禁用按钮，重复新增由唯一约束处理。
2. **用户和部门。** 用户列表只显示本部门的用户名和姓名，可配置角色。部门目录按父部门编号组装成树，初次只展开根层。员工和部门资料由 SQL 维护。
3. **系统和权限目录。** 两个目录只读，系统登记、删除及权限定义的新增、改名和删除由 SQL 维护。移除五个写接口及对应前端操作、请求对象、服务方法、图稿和 OpenAPI 项。Flyway V6 清理数据库中的五个旧按钮码和授予关系。
4. **身份接口。** 保留老师的八个接口，平台共 29 项 HTTP 操作。API 许可返回 `operationId` 与 `allowed`，界面权限检查返回 `allowed`。用户列表响应移除手机号。
5. **课程对接。** 课程适配器集中维护受控路由、操作标识和 API 许可码。同一次课程请求复用已核验的身份，后续请求读取当前授权。课程系统继续使用老师原版前端，菜单和接口分别使用对应权限码。 [课程仓库](https://gitee.com/mingqcn/course-project-mgt)
6. **技术依赖。** 应用数据访问使用 Spring Data JPA。复核教学仓库 `38fd817`，CloneFactory 当前版本是 0.0.2，编译期生成拷贝代码。平台 Java Checkstyle、前端 Prettier、TypeScript 和构建均通过。平台应用源码这轮减少 252 行，统计范围为 `backend/src/main/java` 和 `frontend/src`。 [Spring 教学仓库](https://gitee.com/mingqcn/spring-fundamentals)
7. **演示数据。** 从课程表格导入 10,000 个演示账号的组织归属、111 个来源组织节点和一个演示根节点。账号、姓名和手机号采用合成值。整库现有 10,004 个账号、114 个部门、两个业务系统；导入账号尚未分配角色。导入脚本在本地 MySQL 重复运行后数量一致。 [部署与导入说明](../../deploy/README.md)
8. **图稿与说明书。** 两份说明书均为 A4 纵向。陈氏 ER 图后紧接单张数据库关系图，覆盖八张业务表和一张技术会话表。详细设计先讲总体架构，再讲各功能，时序图放在对应功能下，系统用例图在数据字典之后。保留两套架构类图、完整包图和 DDD 领域对象类图。上一版 PDF 和设计包可从 Git 历史查阅。 [设计交付目录](../redesign/README.md) [图文检查](document-check-v3.8.0.json)
9. **测试与部署。** 平台 37 项、CloneFactory 5 项、平台前端 3 项、课程后端 497 项、课程前端 56 项测试通过。两套实现各通过 68 项公网 HTTP 检查。Chrome 实测六个后台菜单和课程教师登录，普通教师的学期菜单禁用。日志对应六个菜单请求。规模数据已在远程库复核。 [测试汇总](test-summary-v3.8.0.json) [部署与联调记录](deployment-v3.8.0.json)

公网复测对每种实现预热 100 次，并以 8 并发计时 1,000 次。工作负载由界面许可查询和管理员本部门用户分页构成。业务库含 10,004 个账号，用户分页只查询当前部门。结构化 P95 为 146.66 ms，DDD 为 136.95 ms，两轮共 2,000 次均返回 200。 [测量记录](deployment-v3.8.0.json)
