== 引言

=== 编写目的

本文规定当前基线的需求、数据结构、各功能交互、HTTP 契约和双实现设计，供课程评审、开发与验收使用。独立《概要设计说明书》说明系统骨架及 ATAM 评估，本文保存字段字典和各功能详细设计。

本次版本为 3.7.0，基于 v3.2.2 和 2026-11-17 确认决定修订。代码与文档共用功能编号和配置名称，验证结果见实施报告。

=== 背景与术语

平台统一维护用户、部门、角色、业务系统与权限。用户通过角色获得权限；部门限定账号和角色归属及管理员的数据范围。平台自身后台和老师的课程管理系统均登记为接入系统。



[cols="2,6",options="header"]
|===
|术语 |定义
|用户 |员工与登录账号的统一实体，属于一个部门。
|角色 |属于一个部门的权限集合。
|权限 |在一个业务系统内具有唯一编码的操作许可。
|Bearer JWT |客户端在 Authorization 请求头提交的签名凭据，不携带角色或权限。
|登录会话 |服务器保存在 MySQL 的技术记录，关联用户、到期与撤销时间。
|结构化实现 |业务 Service 在事务内编排规则和存储调用。
|DDD 实现 |应用服务编排用例，领域对象维护用户角色分配等业务规则。
|Service Port |两套业务实现共用的用例接口、数据契约和存储端口。
|CloneFactory |老师提供的编译期拷贝工具，生成 DTO 到 Command 的转换代码。
|===

=== 业务约束

[cols="1,7",options="header"]
|===
|编号 |约束
|BR-01 |用户通过角色获得权限；用户角色、角色权限均为多对多关系。
|BR-02 |每个用户和角色属于一个部门；管理员管理本部门直接成员。
|BR-03 |角色分配要求操作者、目标用户、目标角色属于同一部门。
|BR-04 |角色可包含两个业务系统的权限；部门不直接获得系统权限。
|BR-05 |用户名全局唯一、部门内角色名唯一、系统内权限码唯一、系统标识唯一。
|BR-06 |用户名、部门、系统标识、权限所属系统和权限码创建后固定；普通编辑使用字段白名单。
|BR-07 |登录使用用户名和手机号，password 字段承载手机号；systems 接受一组不重复的目标系统。
|BR-08 |成功登录必须拥有目标系统 login 权限；每个受保护请求实时检查会话及登录许可。
|BR-09 |JWT 保存身份和目标系统，会话保存在 MySQL；权限按当前授权关系读取。
|BR-10 |用户和部门通过 SQL 维护。删除角色、权限或业务系统前先处理引用。
|BR-11 |结构化与 DDD 共用输入输出、存储端口和数据库约束；切换配置保持外部行为一致。
|BR-13 |界面码与 API 码分别授予；界面展示和接口执行分别检查，统一复用 RBAC 表。
|BR-14 |RBAC1 角色继承限同部门，支持多级多路径，禁止环；权限按可达角色去重取并集。
|BR-12 |本版功能为单项维护和授权，范围按已确认的精简设计执行。
|===

=== RBAC1 继承约束

高级角色通过 role_inheritance 指向基础角色，获得其直接与间接权限。角色层次与部门层次独立；所有继承边限定同部门。新增边前从基础角色逐层读取继承关系。能走回高级角色时返回 409 ROLE_CYCLE。有效权限查询复用相同的遍历，多路径通过集合去重。移除一条边时其他路径继续有效。

=== 索引、事务与删除

数据库采用 MySQL 8.4 InnoDB，文本使用区分大小写的排序规则。用户名和系统标识建立唯一索引，角色名及权限编码采用所属范围内的联合唯一索引。两组授权和角色继承关联表使用联合主键，并为反向关联列建立索引。

写用例在 Service 事务边界内执行。角色、权限和业务系统存在引用时返回冲突。账号与部门通过 SQL 维护，外键约束仍生效。

关联查询从用户直接角色出发，递归展开 role_inheritance，再通过角色权限读取去重并集。每个鉴权请求检查已提交的授权关系；已进入事务的请求按数据库事务可见性完成。新增授权及继承用 POST，组合主键拒绝重复关系并返回 409。删除关联重复调用仍返回 204。课程演示按单人操作安排。

==== 共享持久化与适配器

ManagementStore 提供业务对象、直接授权与继承边的读写。EffectiveAccessStore 查询有效角色和有效权限，SessionStore 维护技术会话。三个适配器委托给 Spring Data JPA 仓储。新增通过 save 接收自增编号，更新由事务提交时同步受管实体的变化。角色重命名修改受管实体，角色删除时由数据库核对引用。Hibernate 启动时校验 Flyway 维护的表结构。

==== 公共请求 拷贝与事务边界

公开写服务方法使用 @Transactional。Controller 接收到服务结果时事务已完成；保存或提交失败时回滚。唯一及引用约束冲突映射为 409，数据库故障映射为 503，其他未预期错误映射为 500。普通查询和关联查询返回共享 Data，DDD 从 Data 构造领域对象并调用行为。

==== 对象拷贝与运行日志

老师的 CloneFactory 0.0.2 作为编译期注解处理器使用。名称、业务系统登记和权限登记三个 DTO 通过 @CopyTo 声明目标命令。生成的 copy 返回目标 record。教师仓库提交 38fd817 的工具版本为 0.0.2。JPA 将数据库记录映射为持久化实体，适配器将实体转换为 Data，领域对象由应用服务构造。

[cols="2,5,2",options="header"]
|===
|可执行层 |日志内容 |级别

|结构化服务 |用例名称、耗时和执行结果。 |DEBUG / WARN

=== 接口与输入设计

==== 公共约定

平台列表 page 从 0 开始，size 默认为 20、最大 100，page 最大 1000000。平台实体编号在 JSON 中为十进制字符串，避免前端精度损失。老师课程接口保留原分页及编号格式。

路径编号要求正整数。用户名长度 1 至 64，名称 1 至 100，手机号为中国大陆 11 位数字格式。系统标识使用小写字母、数字和连字符；权限码允许大小写字母、数字、点、冒号、下划线和连字符，以兼容 TC、CR 等编码。

新建资源、改名和新增关联使用专用 DTO。未声明字段返回 400。授予权限提交 permissionId，继承角色提交 juniorId。

==== 认证与异常

JWT 使用 RS256，携带 iss、sub、aud、jti、iat 和 exp，默认有效期 30 分钟。BearerFilter 校验签名、到期时间、aud、数据库会话、当前账号及 login 权限。默认使用 aud 首项。X-Target-System 可选择 aud 中另一个已获准系统。

/auth/me 返回 subject、no、name、departmentId、roles、permissions，permissions 只含当前系统的界面码；/auth/users/{userId} 返回 userId、no、name。角色名称用于显示，管理资格由权限集合确定。权限检查返回 allowed 布尔值。统一身份目录按层级和关键词分页查询。部门编码由 D 加现有部门编号组成。课程目录通过 TEC 授权。



[cols="1,3,6",options="header"]
|===
|HTTP |业务码 |含义
|400 |INVALID_ARGUMENT / BAD_REQUEST |字段、格式、分页或路径编号无效。
|401 |UNAUTHORIZED |账号凭据、签名、会话或有效期不通过。
|403 |FORBIDDEN |目标系统登录许可、操作权限或部门边界不通过。
|404 |NOT_FOUND |有操作权限后查找的对象不存在。
|405 |METHOD_NOT_ALLOWED |HTTP 方法不符合接口定义；响应携带 Allow。
|409 |CONFLICT / ROLE_CYCLE |唯一约束、重复分配、引用冲突或角色继承成环。
|500 |INTERNAL_ERROR |未预期错误，写事务回滚。
|503 |SERVICE_UNAVAILABLE |数据库不可用；课程端使用 IDENTITY_SERVICE_UNAVAILABLE 表达身份依赖故障。
|===


==== 独立界面权限与禁用规则

权限实体同时保存界面码和 API 码，两者经同一用户角色、角色权限关系分别授予。数据库沿用八张业务表。GET /auth/me 的 permissions 及 GET /auth/permissions/{permission} 仅返回或判断已登记的界面码。GET /auth/api-permissions/{operationId} 在 AuthService 中映射到 API 码；平台使用 user.list、role.grant 等资源加操作编号，课程保留老师的 operationId。未知操作返回 404 API_OPERATION_NOT_FOUND。

同一管理分组中，拥有任一菜单码时显示全部菜单项；无对应码的菜单使用原生 button disabled。没有管理菜单码时收起管理分组。业务条件满足的操作按钮持续显示，无对应按钮码时 disabled，保存、授予和撤销同样检查。查询与翻页属于菜单基础能力。桌面与移动端共用组件。界面码有效且 API 码缺失时，控件可用，后端返回 403；只有 API 码时控件禁用。窗口重新获得焦点、手动刷新及 403 后重新读取界面码，路由检查菜单权限。

== 性能需求

=== 测量方法

2026-11-17，辅助节点通过公网 HTTP 对两套实现执行同一负载：权限查询与本部门用户列表各占 50%。每轮预热 100 次，再计时 1,000 次；并发为 1、4、8，8 并发各测三轮。登录在计时前完成。数据、连接池、容器资源与 DEBUG 分层日志配置相同。

列表采用有界分页，数据库连接池上限为 5。历史基线数据库含 2 个部门、5 个用户、3 个角色、2 个系统、17 项权限、4 条用户角色和 26 条角色权限关联。v3.4.0 增加独立界面码，该组结果保留为 v3.3.0 部署实测记录；本轮验证见整改报告。测试页容量为 20，本部门列表返回 4 个用户。实时授权查询使用关联表主键及反向索引。

=== 精度与一致性

手机号与系统标识按字符串处理，权限比较区分大小写。角色权限按集合取并集。JWT 不缓存权限；撤销提交后的新请求读取当前关系。写失败回滚，重复分配由数据库联合主键裁决。

两套实现共完成 10,000 次计时请求，全部返回 200，错误率为 0。8 并发三轮 P95 为结构化 36.67 至 52.61 ms、DDD 36.90 至 55.83 ms。结果受 JVM 预热、共享节点和网络波动影响，作为上述数据规模与部署环境的回归基线。

旧版连接复用调整前，1,000 次请求出现 2 次 504（0.2%），网关记录上游连接超时。Nginx 启用 keepalive 后，表中全部请求成功；原始结果及配置见原实施报告。

== 运行需求

=== 配置与启动



[cols="3,5",options="header"]
|===
|配置项 |用途
|BACKEND_STRATEGY |structured 或 ddd，默认 structured，启动时装配。
|DB_URL / DB_USER / DB_PASSWORD |RBAC 数据库连接，凭据由环境或 Secret 注入。
|JWT_PRIVATE_KEY / JWT_PUBLIC_KEY |持久化 RSA 签名密钥和校验公钥的 Resource 路径。
|app.jwt.lifetime |令牌及数据库会话的有效期，默认 30 分钟。
|logging.config / LOG_PATH |Logback 及滚动日志目录。
|===


源码构建使用 Java 21、Spring Boot 4.1.2 和 CloneFactory 0.0.2；前端使用 Vue 3.5、TypeScript 5.7 与 Vite 6。Maven Wrapper 固定版本并使用 HTTPS 镜像。构建与检查入口为 tooling/test.sh。

=== Swarm 部署与恢复

部署复用现有三节点 Swarm，第四台作为辅助节点。管理节点运行两个 JVM 和 Nginx，第一个工作节点运行 MySQL，第二个工作节点保留原应用。数据库及日志使用独立卷，密钥和数据库密码使用 Docker Secret。

演示入口采用 IP 加 HTTP。数据库不发布公网端口，服务通过加密 Overlay 通信。数据需要恢复时，由组员按部署说明手动执行。单管理节点和单数据库实例的故障范围在概要设计中列为架构风险。
