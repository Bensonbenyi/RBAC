| 陈氏 ER 图 | 实体矩形、联系菱形、属性椭圆、键属性下划线；标参与约束与基数；与关系模型对应 | 本课件未提供陈氏 ER 规范，沿用独立的陈氏建模依据 |

接口实现采用 UML realization：虚线加空心三角，指向接口；类继承采用实线加空心三角，指向父类。课件部分示例将接口连接画成实线，重画时按 UML 与 StarUML 官方表示区分。

CloneFactory 按第 24、64 页的静态类调用方式单独表示，不画成 Controller 的自调用。消息写 `command = copy(command, dto)` 等真实操作表达式。创建对象采用创建消息，生命线从创建处开始；静态方法在类图中用下划线表示，并设置模型的静态标记。

alt 表示互斥分支，opt 表示条件执行，loop 表示重复执行。break 仅用于确实需要终止所属交互剩余部分的情形。守卫条件用方括号表达，失败路径不会继续进入成功路径。

排版统一黑白、清晰字体、标准符号，标题用空格分隔。连接线避开文字和无关类框，减少交叉，保证正常缩放可读。UML 的空心三角、实心菱形、生命线、自调用折线等保留标准画法；通用 SVG 风格不改变 UML 符号。课件截图中的裁切、遮挡和字号过小不作为排版模板。

## 第一批图的问题与处理

| 已发现问题 | 重画处理 |
| --- | --- |
| 架构图混合两种实现，说明框过多 | 分开画两套包图，另外说明共享接口和配置选择 |
| 用一条生命线表示多个类或对象 | 拆成独立参与者，标注类型 |
| 用说明文字充当方法消息 | 给接收类定义相应操作，统一参数和返回值 |
| 执行说明使用固定短矩形 | 按调用开始、嵌套与返回位置绘制 |
| 字段、操作类型缺失，关联和依赖混用 | 根据实际持有的成员和临时使用关系重建类图 |
| CloneFactory 画为自身调用 | 使用独立静态类参与者并显示转换调用 |
| DDD 规则与应用编排边界不充分 | 应用服务处理事务与编排，领域对象或必要的领域服务执行规则 |
| 预览与 StarUML 元素不完全一致 | 在 StarUML 中打开核对，逐图对比导出结果；图元可编辑不等于建模正确 |

`assets/design/01` 至 `09` 和 `rbac-design-v1.mdj` 保留作待修改草稿，不能用作已通过评审的交付。上述问题修复并复核后再发布替代版。

## RBAC 范围核对

两套设计使用相同业务规则、API 和七张表，通过配置选择服务实现。结构化版把业务步骤集中在事务脚本；DDD 版将规则落实到领域对象，应用服务协调调用。两套设计应能通过相同业务场景验证。

用户经角色取得权限；部门限定角色归属与管理员可操作范围；权限归属业务系统。继续保留部门与角色关联，不恢复部门与系统直接授权或用户、系统、角色三方表。

登录保持用户名、作为密码输入的手机号、单个目标系统，以及 Session 与 Cookie。对象拷贝使用 CloneFactory，可执行层通过 SLF4J 写入 Logback；接口声明不增加虚构的日志方法。

课件中的支付状态机、领域事件、工厂、缓存及外部支付适配器对应各自业务。当前 RBAC 版按已确认范围设计，不据此增加状态字段、审计、批量操作或新实体。是否绘制状态机由真实生命周期需求决定。

## 交付前复核

- 每条同步调用能在接收类或所实现接口中找到同名、匹配参数的操作。
- 每条关联、依赖、继承和实现关系都有设计依据，箭头方向正确。
- 成功、无权限、资源不存在、重复授权等实际路径有明确结果。
- 结构化版与 DDD 版的职责差异在类图和顺序图中均能看到。
- 配置只装配选定实现，领域层不依赖基础设施实现。
- 类图、顺序图、接口约定和 SQL 中的名称与约束一致。
- PNG 逐张检查，StarUML 原生模型实际打开核对；无文字遮挡、裁切、伪生命线或伪 UML 关系。
