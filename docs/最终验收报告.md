# 统一权限管理系统最终验收报告

日期：2026 年 10 月 8 日。需求基线为 2.1，分析与设计指南为 2.1。此报告区分已经测得的结果、历史失败和课程限制，不把设计指标当作事实。

## 交付与运行

平台、中文管理后台、标准统一认证入口、OA 与知识库模拟系统已实现。构建、启动、停止、纯基础模式、测试及压测步骤见 [README](../README.md)。实际端点、Flyway 迁移、状态归属和事务见 [实现设计记录](实现设计记录.md)。

平台六模块分别为 identity、organization、integration、catalog、authorization、audit，上层 application 协调员工生命周期。模拟系统无平台数据库依赖。Google Java 格式、中文职责注释、真实 MySQL 竞争测试和 ArchUnit 用于检验实现是否遵守设计。

基础导入保留 10 公司、101 部门、10,000 员工、54 名部门待确认员工、17 外部系统、85 个模板和 772 个具体权限动作。普通岗位不自动变成管理员，也不自动授权。演示配置与专用压测配置分别叠加，来源表格未修改。

## 性能环境与测量边界

本机为 MacBook，Apple M5 Pro，15 个 CPU，48 GiB 内存，macOS 26.6.2。平台与 Gatling 在同机运行，MySQL 8.4.11 位于 OrbStack 容器，端口 3307。OrbStack 虚拟机可用 15 CPU、约 15.7 GiB 内存，容器没有另设 CPU 或内存上限。Java 21.0.11，Maven 3.9.16，Node.js 24.16。完整配置见 [environment.json](verification/environment.json)。

平台 `-Xms1g -Xmx4g`，Hikari 最大 24 连接，连接等待上限两秒；`UPMS_DB=upms_load`、`UPMS_SEED=load`、业务权限缓存关闭。后台写入最多四个请求同时进入用例，等待两秒后明确返回 503。系统凭据成功校验缓存最多 256 项，两分钟绝对期限，含当前存储哈希，错误凭据不缓存。

压测使用 10,000 个不同账号，9,946 人在各自确认部门拥有 OA 普通角色，54 人明确预期拒绝。100 名专用最高管理员为 SG001000 至 SG001099。管理员循环执行员工查询、详情和本人资料维护，每轮思考一秒；持续鉴权每秒注入 1,000 次，五分钟计划 300,000 次。混合负载同时施加两组，不顺序替代。

完整登录组包含六次 HTTP：授权入口、登录页及 CSRF、资料匹配、取得码、后端兑换、UserInfo；客户端同时校验 state、签名、issuer、audience、nonce 和期限。统计组经过时间，不用六次 HTTP 耗时简单相加冒充端到端登录。加载后的会话固定期限，不发刷新令牌。

鉴权计时为平台 HTTP 往返。200 且 allowed=false 可以是正确业务拒绝；技术异常另计失败。脚本将实际判断与每个账号预期比较，错误判断数必须为零。原始 Gatling 日志为二进制，压缩包可还原完整原生报告。HTML 摘要与控制台 HDR 百分位可能相差一毫秒，验收断言以控制台为准。

| 验收 | 发起及完成量 | 测量结果 | 状态 |

| ACC-P-001 | 10,000 账号／60 秒，60,000 HTTP 全部完成 | 最终独立实例完整登录 P95 26 ms，账号技术失败 0；另保留优化后 P95 2,224 ms、失败 0 的测量 | 通过 |
| ACC-P-002 | 1,000 次／秒，300 秒，共 300,000 | 无业务缓存 P95 10 ms，技术失败 0，错误判断 0 | 通过 |
| ACC-P-003 | 100 管理员，300 秒，87,700 HTTP | 查询／详情／写入 P95 9／9／41 ms，技术失败 0 | 通过 |
| ACC-P-004 | 300,000 次鉴权并行 100 管理员，共 387,503 HTTP | 鉴权 P95 14 ms；管理查询／详情／写入 12／12／18 ms；技术失败与错误判断均为 0 | 通过 |
| ACC-P-005 | 持续 1,000 次／秒背景鉴权下真实变更，背景 90,000 次 | 九项变更首次正确响应 5 至 15 ms；三秒后的探针无错误，独立浏览器保留；背景技术失败和错误判断均为 0 | 通过 |

登录最终轮在重启的独立实例运行，包含首次凭据校验，后续请求在同一轮中复用成功缓存。其它达标轮次的 P95 为 14 ms 与 2,224 ms，分别保留，不能将任何一次结果推断为所有环境均能达到。一次测量发生机器休眠及时钟跳变，出现一笔授权码技术失败，单独归档，不用于替代完整 10,000 已登录账号输入。后续正式测量启用防休眠。

300 秒注入结束后等待尾部请求，鉴权单测报告的分母为 301 秒，混合负载按管理员尾部统计至 304 秒；验收同时核对实际注入速率、总数、完成数和积压，不能仅凭百分位忽略吞吐。

正式原始证据包括 [登录](verification/performance/raw/login-final.tar.gz)、[鉴权](verification/performance/raw/authz-final.tar.gz)、[管理员](verification/performance/raw/admin-final.tar.gz)、[混合负载](verification/performance/raw/mixed-final.tar.gz)和[变更背景](verification/performance/raw/changes-background.tar.gz)。解压后可直接打开 index.html，原始二进制 simulation.log 与控制台断言同时保留。SHA-256 清单位于 [SHA256SUMS](verification/performance/raw/SHA256SUMS)。

### 失败、定位与复测

| 测量 | 发现 | 改动与代价 |
| --- | --- | --- |
| 初始登录诊断 | 客户端 Accept 配置与连接策略错误，组计时方式需要校准 | 使用正确资源类型、连接池及组经过时间；Cookie 仍按虚拟用户隔离 |
| 无凭据缓存完整登录 | P95 约 17.3 秒，1,850 个账号失败；JFR 样本集中于 BCrypt | 仅成功凭据结果有限复用，首次仍用框架哈希；额外承担凭据缓存边界测试 |
| 首次混合负载 | 鉴权 P95 4,866 ms，489 次技术失败；管理写事务等待治理锁占满连接池 | 排队移至事务之前，四许可公平闸门；粗治理锁保留，需要接受写入吞吐受限和饱和 503 |
| 反复完整登录 | 同一实例累积至会话保护上限，最后一轮 102 个账号被拒绝 | 保留容量边界结果；独立正式实验先重启单节点，而不增加上限掩盖前轮残留会话 |

原始 JSON 见 [performance 目录](verification/performance/)，失败轮同样保留。变更逐次采样在 [change-deadlines.json](verification/performance/change-deadlines.json)，每个变更先验证相反的旧状态，再成功提交，约每 50 毫秒采样至 3.5 秒；401／403 按对应入口解释，503 或连接失败不会冒充正确拒绝。有限实验验证这些采样请求，不能证明所有未来调度都满足期限；版本锁、实时身份核验及缓存绝对期限承担设计约束。业务权限快照默认关闭，测量没有给出引入 Redis 或消息队列的必要性。

## 设计与代码一致性

[指南第 8.1 节对应表](统一权限管理系统分析与设计指南.md#81-需求模块代码与场景)已用实际代码替换“待实现”。阅读一个场景时可由需求编号进入 DFD，再定位模块公开能力和用例，最后查看测试。实际接口在实现记录，不回写需求文档为技术说明。

ArchUnit 检查跨模块仅使用 api、业务模块无循环、模块不反向依赖 application、控制器不直接访问内部持久化，以及纯有效权限规则不依赖 Spring、JPA 或 Web。事务竞争测试检查数据库结果；源码依赖测试不能代替运行一致性验证。

员工停用通过 EmployeeLifecycle 协调事务内状态／撤权／审计与提交后会话失效；单角色写入通过治理锁、员工锁、系统锁、角色锁、版本和唯一键约束。目录停用移除角色选择，新项及重新启用均需显式授权。普通查询和实时鉴权不取治理锁。

课程认证使用用户名和手机号，无密码或短信，不能视为生产身份校验。17 系统只有登记和目录数据，OA 与知识库只是权限不同的演示业务。单节点重启清空统一会话、协议授权与签名密钥，业务配置保留；模拟记录本身为演示内存数据。统一会话有约 30,000 项保护上限，超过后拒绝新登录；万人性能目标已在独立实验中验证，未承诺无限浏览器会话容量。

协议授权状态及令牌索引也有界，分别最多 50,000 和 200,000 项，容量淘汰后安全拒绝并要求重新认证。本轮未测万人同时访问全部 17 个系统；正式负载按已确认的完整登录与轮转鉴权构成执行。

审计故障明确缺口，不承诺可靠补录。没有多节点、多活容灾或生产合规验收。前端 Element Plus 构建包较大，本轮未以页面首次下载指标验收。性能结果受同机环境影响，换硬件或拆锁、改缓存后需重新跑正式负载。
