# 集团统一权限管理系统

OOAD 课程项目。平台管理身份、统一会话和 RBAC0 权限，OA 与知识库独立运行。管理员维护权限，员工从业务系统跳转统一登录；每次受控操作重新鉴权。

行为见 [需求规格 2.1](docs/统一权限管理系统需求规格说明书.md)，模块与架构推导见 [分析与设计指南](docs/统一权限管理系统分析与设计指南.md)，操作契约、ER 与持久化推导见 [接口与数据库设计指南](docs/统一权限管理系统接口与数据库设计指南.md)，实际端点速查见 [实现设计记录](docs/实现设计记录.md)，验收数据见 [最终报告](docs/最终验收报告.md)。

## 本机启动

需要 Java 21、Node.js 24 和可用的 Docker Compose。Maven Wrapper、前端锁文件已包含在仓库中。首次构建会下载依赖。

```bash
bash scripts/build.sh
bash scripts/start.sh
```

| 应用 | 地址 | 作用 |
| --- | --- | --- |
| 管理后台 | http://localhost:18080/admin | 员工、组织、角色、授权、目录与审计 |
| OA | http://localhost:18081 | 查看、创建记录及本人记录校验 |
| 知识库 | http://localhost:18082 | 与 OA 不同的权限配置 |
| MySQL 8.4 | 127.0.0.1:3307 | 项目专用 Compose 容器 |

后台构建产物已由构建脚本放入平台 JAR，启动无需另跑前端开发服务。开发时可运行 `npm --prefix frontend run dev`，地址为 http://localhost:15173，通过 Vite 代理访问平台。

停止使用 `bash scripts/stop.sh`，保留数据库卷。日志在 `.runtime/`。脚本检查端口占用和启动就绪，不覆盖运行中的 JAR；修改代码后先停止，再构建和启动。模拟系统启动前需要平台就绪。

需要由终端或 CI 保持父进程时使用 `bash scripts/start.sh demo --foreground`，另一个终端执行测试或停止；纯基础模式同样接受 `--foreground`。

本机数据库用户为 `upms`，默认密码 `upms-local`，root 密码 `upms-local-root`。仅用于本机课程环境，可通过 Compose 环境变量改写。Cookie 为 HttpOnly，使用 localhost HTTP，因此不设置生产 HTTPS Cookie 策略。请统一使用 `localhost` 访问页面，避免与 `127.0.0.1` 混用导致回调或会话不一致。

## 演示账号与步骤

登录同时输入用户名和手机号，没有密码或短信。这是已确认的课程简化校验。

| 身份 | 用户名 | 手机号 | 演示用途 |
| --- | --- | --- | --- |
| 最高管理员 | SG000001 | 13976537502 | 全局管理 |
| 普通员工 | SG000013 | 13554810349 | 已授予两个模拟系统的演示角色 |
| 未授权普通员工 | SG000020 | 18921085097 | 可确认身份，但业务操作拒绝、后台拒绝 |

部门管理员为 SG000011、SG000051，第二名最高管理员为 SG000002。手机号可由最高管理员查看员工详情；这些身份均是显式演示叠加，不由来源岗位推断。

1. 用最高管理员进入后台，查看公司、部门、系统目录和全局模板。模板须复制为部门角色才能分配。
2. 在 OA 用 SG000013 登录并查看、创建记录。同一浏览器进入知识库，免再次输入身份资料；查看允许，新增拒绝。
3. OA 中“本人记录”默认请求其它员工的记录，应拒绝；改为记录 1 后允许。记录所有者检查属于业务系统。
4. 后台查询 SG000013 的有效权限，撤销 OA 角色；再执行 OA 受控操作，最迟三秒拒绝，知识库角色独立。重新分配演示角色可恢复 OA 操作。
5. 在 OA 统一退出，知识库下次受控操作拒绝。同账号另一浏览器的独立会话不受此次退出影响。
6. 展示批量任务逐项结果、并发旧版本冲突、部门隔离及审计筛选导出。调动须先撤掉全部系统角色并等待生效，最高管理员调动后由新部门重新授权。

## 数据模式

三份教师 Excel 保持原样。基础数据包括 10,000 员工、10 公司、101 部门、17 外部系统、85 模板及 772 个具体权限动作；54 名公司直属员工保留“待确认部门”，没有猜测归属。

| 数据库 | 模式 | 用途 |
| --- | --- | --- |
| upms | demo | 基础资料与明确标记的少量演示授权 |
| upms_baseline | baseline | 纯基础资料，没有管理员、部门角色或业务分配 |
| upms_test | baseline + 测试夹具 | 真实 MySQL 集成测试；不运行演示服务 |
| upms_load | load | 独立压测副本与 100 名专用管理员 |

`bash scripts/start.sh baseline` 使用独立基础库，不清除演示库。纯基础模式可统一确认员工身份，没有后台使用资格。各模式首次导入及叠加都有标记，重复启动保留管理变更；改初始化模式不会自动撤掉已经叠加的数据。

## 检查与正式压测

```bash
bash scripts/test.sh
# 先以 demo 模式启动三个应用，再执行浏览器测试。
npm --prefix frontend run test:e2e
```

后端检查包含 Google Java 格式、Checkstyle、JUnit、真实 MySQL 事务竞争和 ArchUnit 边界；前端包含 ESLint、Prettier、TypeScript 与 Playwright。测试不能指向演示数据库。

```bash
bash scripts/stop.sh
bash scripts/start-load.sh
bash scripts/load-test.sh all
bash scripts/stop.sh
bash scripts/start.sh
```

完整正式压测约需 20 分钟，先完成 10,000 账号登录并写出令牌输入，再分别测鉴权、管理员、混合负载及变更期限。macOS 下脚本在测量期间阻止空闲休眠。运行时令牌只放在被 Git 忽略的 `.runtime/load/`，不提交或归档。

可分别运行 `login`、`authz`、`admin`、`mixed`、`changes`。后四项必须使用当前平台实例签发的 10,000 个不同账号令牌，平台重启后先重跑 `login`。每轮完整实验先重启压测平台；反复执行登录会累积固定八小时会话，单节点约 30,000 会话的保护上限可能拒绝新登录。变更测试会结束受测员工会话，之后再测轮转全部员工时须重新登录。不得并行写入和读取令牌文件，也不要同时运行集成测试、打包或其他压测干扰正式测量。

JSON 摘要、控制台断言和含原始二进制日志的 Gatling 报告压缩包保存在 `docs/verification/performance/`。不达标轮次同样保留。变更测试恢复被修改员工的原角色与状态；专用目录项保留，以免删除历史目录造成不完整上报。

## 实现边界

平台是模块化单体，使用 Spring Boot 3.5.16、Spring Authorization Server 1.5.8、Spring MVC、JPA 和 MySQL 8.4。六个模块经公开能力协作，复杂有效权限规则独立于框架。前端为 Vue 3、TypeScript 与 Element Plus。

业务权限缓存默认关闭；有界 Caffeine 快照可作为实验启用。Redis、消息队列、微服务不在本期依赖中。管理写入使用事务前有限排队与固定锁顺序，成功审计和变更共同提交。

17 个外部系统仅导入登记与目录，完整业务只演示 OA 和知识库。统一会话及协议授权在单节点内存中，重启须重新登录；业务资料持久保存。不承诺生产认证强度、多活容灾或故障审计补录。正式指标是本机指定环境的测量结果，不能直接推断其它硬件的容量。
